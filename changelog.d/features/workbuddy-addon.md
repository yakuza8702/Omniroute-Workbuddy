- **feat(workbuddy):** new **WorkBuddy addon** — the WorkBuddy desktop app's 国内版 (`workbuddy` / `wb`) and International (`workbuddy-global` / `wbg`) editions join OmniRoute as first-class providers. Accounts are imported read-only from the installed app (live sign-in first, timestamped backups as extra accounts), the model roster is read from each edition's own directory (CN `/v2/enterprises/personal/models`, global `/v3/config` as the desktop channel), and chat routes through the edition's gateway with per-account identity headers and a guaranteed leading system message. Beyond a plain gateway integration the addon exposes the WorkBuddy account surfaces: credit balance (`GET /api/workbuddy/credits`), credit claim / daily check-in (`GET|POST /api/workbuddy/checkin`, never automatic), the current free model (zero-rate entries from the live catalogue, `GET /api/workbuddy/free-model`), and a machine-readable description of how the addon works (`GET /api/workbuddy/info`). Multiple accounts work the platform's way: each imported sign-in is its own connection (routing, priority and failover stay the router's job), the overview routes answer for the first enabled account in the router's own order and accept `?connectionId=` to target a specific one — including a per-account `POST /api/workbuddy/checkin` claim. Every `/api/workbuddy/*` route is loopback-only; tokens never reach the browser (discovery exchanges a sha256 fingerprint and the server re-reads the auth files on import).
